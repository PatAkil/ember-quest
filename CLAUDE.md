# Ember Quest

A roguelike JRPG — branching node map per act, turn-based one-on-one battles,
skill points, a loot table of named items, permadeath. TypeScript + Canvas 2D,
no framework. This repo holds **one game**; it was forked out of Retrovibe so
the game can grow on its own. Live at **https://patakil.github.io/ember-quest/**.

## Conventions

- **Commands run at the repo root**: `dev` (Vite, port 5173, strictPort), `check`
  (`tsc --noEmit`), `build`, `smoke`, `sim`.
- **Dev server lifecycle is port-based**: reclaim with `lsof -ti:5173 | xargs -r kill`;
  launch `npm run dev` in the background and poll for `Local:   http://localhost:5173/`.
  Launch it at the start of a session and leave it up — every save hot-reloads.
- **Done means**: `npm run check` after every edit; `npm run build` **and**
  `npm run smoke` green before a commit; `npm run sim` reviewed whenever rules or
  numbers moved. The user is the playtester — Claude reports "builds, boots clean,
  ready to play at <URL>", never "playtested".
- **Commit at green milestones, unsigned** (`commit.gpgsign=false` in this repo's
  config). Message = what changed for the player. `git add -A` is fine here: the
  repo is the game.
- **Push = release.** Only through **releasing-the-game**, only after the gates.
- **Headless boundary**: `game/data/*` and `game/sim/*` never import the engine,
  the DOM, `localStorage` or `Math.random` (rng is injected). Rules live in
  `game/sim/*`; `main.ts` and `game/screens/*` present them. Break this and the
  simulator stops bundling.
- **DESIGN.md moves with the code.** A rules change edits the contract in the same
  milestone; a balance pass updates the *Balance state* table and its date.
- **Art is verified by looking.** `node tools/capture.mjs sheets` (line-ups in colour, greyscale and
  silhouette, every actor's pose sheet, `tools/out/metrics.md` against ART-REVIEW.md's ship criteria),
  `battle` (title → room card → battle frames incl. a hit, pause, inspect), `phone` (the same on a touch
  viewport), `playfull [acts=1] [phone=1] [ko=1] [seed=N]` (drives a whole run by tapping contract
  geometry — draft, SUMMON, leader, map, every node kind, battle, cards, doors, bank — one frame per
  distinct screen, `PLAYFULL OK` and a `playfull-decisions.json` that replays headlessly with `seed`;
  `play` is its `acts=1` alias), `shot url=<dev page> name=<n> [phone=1]` (any page that sets
  `window.__lineup.ready`; `/tools/screens.html?screen=…&fixture=…` renders any run screen from
  fixtures). Needs the dev server; long captures run on a snapshot server while other writers are
  saving, because a hot reload resets the run. An art or scene change is not done until its sheets and frames have been opened and judged. An in-scene number is measured with `node tools/seats.mjs`, never rebuilt per session: it reads the
  stage anchors out of `game/screens/layout.ts` at runtime and records the commit and the anchors in
  every capture, which is what decision 3 after round 14 requires. The sheet rulers are
  `node tools/rulers.mjs` (`hash` for byte identity between two trees); frame probes are `node tools/probe.mjs`.
- **Engine edits are allowed** — the engine here is a fork owned by this game.
  New primitives go into the owning module, are re-exported from `engine/index.ts`,
  and are added to the API table below in the same change. There is no fixture
  verification loop here; a visual change is verified by building, smoking, and
  the user looking at it.

## Models & orchestration

`.claude/agents/game-writer.md` (Sonnet-class) writes code in milestone saves with
`npm run check` after each. The orchestrator owns the dev server, smoke, sim, and
git. **Escalation rule**: if check or smoke fails twice on the same approach,
escalate the writer one tier (Sonnet → Opus) for a fresh attempt. **Design first**:
mechanics changes go through `designing-mechanics` and a decision by the user
before code moves; parallel writers are fine once the contract is written, split
by module (data+sim vs sprites+main) so they do not collide.
If ember-quest is not the session's PRIMARY repo, `game-writer` resolves to the
primary repo's definition (retrovibe's is scoped to `workspace/<game>` and refuses these
paths): run writers, verifiers and critics as `general-purpose` agents with an explicit
model instead, and start the next session with ember-quest as the primary repo
(STATUS.md, "Session mechanics learned the hard way").

A `BiomeLook` is DATA — key/fill lights, ONE OR TWO floor pools (`pool`, plus an optional `pool2`), grade + vignette, fog, motes, shafts, rim colour, an ambient preset for particles.ts, and four `PlanePainter`s (far · mid · floor · near). **The pools are a symmetric pair**: the stage is a diagonal with the enemies on one third and the party on the other, so a single centred pool peaks where nobody stands and leaves half the diagonal unlit — every biome in `backdrops.ts` now sets both, at the two foot clusters. Everything is baked ONCE per (biome, tier): the four planes into padded offscreens with the blur baked in (`ctx.filter`, or a down/up-sample fallback) — **except the FLOOR, which bakes CRISP**: `BLUR_FLOOR = 0` and `bakePlane(…, crisp)` draws that painter at 1:1 inside the padding instead of through the plane's usual `padScale` (1.1111 on a 1280×720 frame — the height drives it, and the same helper is now the single definition `bakePlane`, `bakeFlat` and the sky body all read) (it pays for the lost bleed by stretching the finished plane's outermost row and column outwards), because the ground is at the actor plane's own depth and `backdrops.ts` now authors it in hard pixels on the actors' own 2-px cell. At 1.1111 every cell landed on a fractional boundary and a 2-px stone arrived as a 3-px gradient; with the blur and the scale both gone the floor's p10→p90 in the near band went 4.4 L → 28–39 across the six biomes. The floor is therefore the ONE plane not at the pad scale: its geometry no longer registers horizontally with far/mid/near (≈ 49 px of disagreement at the frame edges). Nothing registers across those planes today, but a prop that must sit on a named ground feature has to know it. FAR (6 px) and NEAR (8) keep their blur; **MID came down to 1.2 in round 6** — at 2.6 the plane the architecture lives on (arches, hanging chains, lamps, a lit doorway, brick coursing) was drawn and invisible, which `r3-bd-CRYPT-ARCADE.png` proved by showing all of it on the unblurred flat bake — that split is the depth of field, and it is what DESIGN.md's one-plane rule was protecting (amended: see `tools/out/CONTRACT-EDITS-3.md`). **MED, which folds mid and floor into one plane, rasterises the two painters onto SEPARATE offscreens** and composites them before the blur: on a shared canvas `backdrops.ts`'s `fadeTop` feathers the floor's top edge with `'destination-out'` and erased straight through the mid content beneath it, leaving a full-width joint (a 1171-px straight run at y 379 on `bd-SUNKEN_VAULT` at MED against 277 px as that frame's longest run at HIGH; 258 after). Same plane count, same per-frame cost, one extra bake-time canvas, the whole light rig (key + fill + pool + shafts + the HIGH highlight lift) flattened into ONE bitmap, and the grade + vignette into an opaque multiply map. A frame then draws bitmaps: `renderBackground` (far · mid · floor · **near** at their parallax offsets — depth < 1 lags the camera shake, and the planes are oversized by `PLANE_PAD = 40` so no edge shows — **then the light map at `'lighter'`**), actors, `renderLightPlane` (**the per-actor light** — the gain, the rim spill and a lit prop's floor pool, as baked sprites; the drifting fog and the seeded dust motes moved OUT of it in round 5, up into `renderBackground` behind the actors), `renderPost` (bloom, the grade, then the **sky body**). **THE ADDITIVE WASH IS APPLIED BEFORE THE ACTORS, NOT OVER THEM.** An additive term is a constant in sRGB and sRGB is very nearly linear in L*, so a full-screen `'lighter'` blit moved every cell of a sprite by the same number of L: measured per component on masked actor cells, the light map alone put **+19.5 L** on cells authored below L 35 and **+11.7** on cells above L 65 (CRYPT_WARDEN at enemy slot 1), the bloom another +4.6 to +10.9, and the grade's multiply then took −10.0 off the darks and −16.6 off the lights — an authored range of L 25 → 74 arriving as L 46 → 76. Moving the blit up into `renderBackground` keeps the diorama's light exactly as it was (**the six backdrop captures at `actors=0` are byte-identical**) and takes it off the actor plane; the near plane moves with it so the plane order is unchanged, which is safe only because this diorama's foreground never overlaps an actor (curtains ramp out by x 150–186, `floorLip` starts below the front rank's feet at y 516). **The actor plane is then lit MULTIPLICATIVELY**: one baked flat-colour sprite drawn `'color-dodge'` per actor, which is `dest / (1 - src)` — a per-channel gain — and with a flat colour under a feathered alpha the compositing formula collapses to `out = dest * (1 + a * (G - 1))`, exactly linear in `globalAlpha`, so one bitmap covers the whole strength band with no readback and no per-frame allocation. `GAIN_FLOOR 0.06` is what an actor outside every pool gets and `GAIN_LIFT 0.24` what a fully-lit one gets on top (both came down again in round 6 when the pools lifted the ground under the seats by 15–20 L: a gain tuned against a dark floor puts the sprites back on top of a bright one, and the reference's law is dark figures on a lit ground) (the floor was 0.30 so an unlit actor did not land below its own sheet after the grade's ≈ ×0.80; on round 4's lit floor that is the wrong side to err on — the reference's law is dark sprites on a BRIGHT ground — and 0.30 cost the hero value bar 25 seat-readings), `GAIN_TINT 0.45` mixes the rim colour toward white, and the ellipse is a tight `0.66 × 0.98` of the box because two gains MULTIPLY where two washes only added. **THE SOURCE TEST IS AT THE FEET, AND THE SPREAD IS CAPPED.** Which light is on a body is asked at `a.y + a.h` — the ground it stands on — not at its centre of mass: the pools are ellipses on the floor line with `ry ≈ 116` and a standing figure's chest is ~65 px above its feet, so an actor standing squarely IN a pool had its chest tested near that ellipse's edge and the seats in the brightest light drew the LEAST gain (crypt enemy-1 has the brightest ground strip of the six, relY 122 against 87–104, and drew the lowest reach, 0.23; at the feet it draws 0.62, and the near hero seat drops 0.83 → 0.55). The gain and the spill are still CENTRED on the body; only the question moved. Then `GAIN_SPREAD_CAP 0.14` clamps every body's reach into a band around the MEDIAN body's in the same frame — the review's rule is that no seat's torso p50 may sit more than 5 L above the median seat's, geometry alone cannot deliver it because the pools have to stay where the feet are, and this is relative so a frame of one actor is unchanged and a `'vfx'` box is excluded from the median and never capped. Measured with ONE sprite planted at all six anchors, six biomes at HIGH: seat spread **4.5 L max** (was 8.2 in the crypt), rig contribution **+5.25 to +6.08 L on the hero seats against +3.19 to +4.37 on the enemy seats** in every biome — the rig does not favour the enemy rank. The rim spill stays as the small additive half (`RIM_FLOOR`/`RIM_LIFT` halved to 0.04/0.06) and is drawn AFTER the gain — multiply first, then add the floor. Same law on both sides of the stage. Measured on the actors' own masked cells, the same frame, same poses: lift on cells authored below L 35 goes CRYPT_WARDEN +20.4 → **+5.4**, ASH_HOUND +11.9 → +2.3, CINDER_IMP +13.8 → +5.3, TIDE +16.3 → +9.8; on cells above L 65 the actors now keep their own values. The **bloom** was the last additive term on a sprite and round 5 took it off the actor plane: `BLOOM_ACTOR_DAMP` punches one `'destination-out'` ellipse per body — the gain's own ellipse — out of the half-res bloom buffer inside its refresh branch, from a mask baked once, so at most sixteen draws over 640×360 with no readback and no allocation. The mask feathers, so a lit prop's halo survives in the air around it, and a `'vfx'` box is never damped: an effect IS the bright thing the bloom exists to catch. **`LightActor.kind` (optional, `'actor'` by default — an absent field changes nothing) marks a box as an EFFECT'S BOUNDS rather than a body**: a `'vfx'` box is given its glow (the floor pool and the bloom seed) and neither the `'color-dodge'` gain nor the rim spill, because `battle.ts` feeds every effect's `vfxBounds` through the same `addLightActor` the fighters use and a gain over a 0.66 × 0.98 ellipse of a 515 × 674 effect box is what turned a hit target white (its share above L 75 at impact: 25.8 % from the sprite's own flash, 67.5 % with the effect's box fed in). `drawContactShadow(ctx, feetX, feetY, w)` is a hard two-row ellipse at 0.34 alpha with a 0.30 core, plus a soft CAST LOBE leaning down-and-right away from the key — centred at (x + 0.62·rx, y + 3.4·ry) with a radius of **3.0× the contact radius** at `SHADOW_CAST_ALPHA 0.82`, foreshortened to `SHADOW_CAST_SQUASH 0.50`, drawn from the module's gradient cache so it allocates nothing (it was 2.3× centred at y + 1.7·ry with a 0.42 squash, reaching ~12 px past the boots; round 6's pools took the ground inside each cluster to p50 44.8–59.7, and on a floor that bright the shadow has to reach the ~40 px where the review's second ground strip is measured) — call it before the actor. The lobe is the actor-plane lever for the in-scene contrast ruler: the ground an actor is measured against is the ground it stands on, and a figure on a lit floor casts a shadow on it. It took actor-median-vs-ground ≥ 1.5:1 at both strips from 66/108 to 106/108 on the tuning set. The two contact ellipses are unchanged, so the HP hairline still tucks into them. (It was 0.46/0.50 while the wash still ran over the top of it and lifted it; drawn on an already-lit floor those numbers read as a black sticker.) The per-actor GAIN and RIM SPILL are driven off the NEAREST light: each actor's centre is tested against key, fill and both pools (elliptical reach, alpha × **`actorWeight`** as weight) and the strongest sets the gain's strength and both the spill's alpha (`RIM_FLOOR 0.04` up to `RIM_FLOOR + RIM_LIFT` at `RIM_REF`, so an actor outside every pool is dim but never black) and its lean, blended halfway back toward the key because the sprites' own baked rim is upper-left in every biome. The grade's VIGNETTE is an ELLIPSE, built on a unit circle and scaled to `VIGNETTE_RX/RY` (0.72 x 0.78 of the frame): a circular falloff on 16:9 ran out of gradient before the side edges and piled its last stops into a band down each side with a straight inner boundary. `bakeFlat` (the LOW/ARCADE flatten) gives each painter its OWN layer — a painter may use `'destination-out'` on itself to feather its own joint, and sharing one canvas turned that into an erase through the planes behind it. **`actorWeight` (optional, default 1, on `KeyLight` and `PoolLight`) is how much of a source counts as light ON A BODY** — it scales nothing that is baked into the light map, so the diorama is untouched whatever it says. It exists because the two are different jobs: the crypt's key is architecture light, high and up-stage LEFT, which is where the enemies stand, so weighted 1:1 the rig lit the enemy rank harder than the party at every seat (source reach at the six feet anchors 0.143 / 0.107 / 0.119 on the left against 0.050 / 0.080 / 0.125 on the right) — half of why three critics read the frame left-first. Every biome now sets key 0.5, fill 1.4, pool 0.85, pool2 **1.25** — pool2 is the party's, and the enemy rank was averaging 8.0 L above the plane the player controls; the fix is on the party's side. **The two foot pools are DERIVED, not typed**: `backdrops.ts`'s `clusterPool` reads `layout.ts`'s exported `HERO_FEET` / `ENEMY_FEET` and builds each ellipse around its own rank, so a composition round that moves the anchors moves the light with them.
